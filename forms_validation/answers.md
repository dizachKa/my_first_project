# Ответы на вопросы для самоконтроля (ПР7)

## 1. Какие HTML5-атрибуты используются для клиентской валидации?

- `required` — поле обязательно.
- `minlength` / `maxlength` — минимальная/максимальная длина текста.
- `min` / `max` — границы для чисел и дат.
- `type` (email, tel, url, number, date) — задаёт формат.
- `pattern` — регулярное выражение для проверки.
- `step` — шаг для числовых полей.

Они дают базовую валидацию без JavaScript.

---

## 2. В чем разница между `novalidate` и отключением валидации через JavaScript?

`novalidate` на `<form>` отключает встроенную браузерную валидацию (сообщения браузера). Но проверки `checkValidity()` в JavaScript продолжают работать. Отключение через JS (`form.noValidate = true`) даёт тот же эффект. Разница в том, что `novalidate` — это декларативный атрибут в HTML, а JS — динамическое управление.

Мы используем `novalidate`, чтобы браузер не показывал свои всплывающие сообщения, а мы показывали свои.

## 3. Как правильно связать `<label>` с полем ввода?

Через атрибут `for` у `<label>` и `id` у `<input>`:
```html
<label for="email">Email</label>
<input type="email" id="email">
Это важно для доступности: скринридеры читают связку, а клик по label фокусирует поле.

4. Какие типы input подходят для разных данных?
text — имя, фамилия.

email — почта.

tel — телефон.

password — пароль.

date — дата рождения.

number — числа.

url — ссылки.

checkbox / radio — выбор.

5. Как работает валидация с помощью pattern?
pattern задаёт регулярное выражение. Если введённое значение не соответствует — поле считается невалидным, а field.validity.patternMismatch становится true.

Пример для телефона:

html
pattern="\+?[0-9]{1,3}\s?\(?[0-9]{1,5}\)?\s?[0-9]{1,3}[-]?[0-9]{2}[-]?[0-9]{2}"
6. Какие события JavaScript используются для валидации в реальном времени?
blur — когда пользователь уходит с поля.

input — при каждом вводе символа.

submit — при отправке формы.

blur удобно для показа ошибки, input — чтобы быстро её убрать.

7. Как обеспечить доступность сообщений об ошибках для скринридеров?
Связывать сообщение с полем через aria-describedby.

Использовать aria-invalid="true" на невалидном поле.

Добавлять role="alert" к сообщениям об ошибках.

Не полагаться только на цвет — добавлять текст.

8. В чем преимущества fieldset и legend?
fieldset группирует связанные поля, legend даёт название группы. Это улучшает семантику, доступность и UX. Скринридеры зачитывают legend перед полями группы.

9. Как реализовать кастомную валидацию (например, подтверждение пароля)?
Через JS: сравнить значения двух полей и показать ошибку, если не совпадают.

js
if (password.value !== confirmPassword.value) {
    showError('Пароли не совпадают');
}
10. Какие методы CSS используются для отображения состояний валидности?
Псевдоклассы:

:valid — валидное поле.

:invalid — невалидное.

:focus — поле в фокусе.

:placeholder-shown — пустое поле с placeholder.

Плюс класс .error, который добавляется через JS, и анимация shake для привлечения внимания.
