
# Ответы на вопросы для самоконтроля

## 1. Три основные области работы с файлами в Git и чем они отличаются?

- Рабочая папка (Working Directory) — текущие файлы на диске, с которыми работает пользователь.
- Индекс (Staging Area) — промежуточная область, куда попадают изменения после команды git add. То, что войдёт в следующий коммит.
- Репозиторий (Repository, папка .git) — хранилище зафиксированных коммитов, полная история версий проекта.

Отличие: рабочая папка — это «черновик», индекс — «подготовлено к фиксации», репозиторий — «зафиксировано».

## 2. Что происходит при выполнении команд: git add, git commit, git push?

- git add — добавляет изменения из рабочей папки в индекс (подготавливает к коммиту).
- git commit — фиксирует содержимое индекса в репозитории, создаёт новую версию с сообщением.
- git push — отправляет локальные коммиты в удалённый репозиторий (например, на GitHub).

## 3. Почему важно писать информативные сообщения к коммитам?

Чтобы по истории было понятно, что и зачем менялось. Это помогает ориентироваться в проекте, искать причины ошибок
 и откатывать изменения. Сообщения вроде "исправление" или "update" не несут полезной информации.

## 4. Чем отличается git add имя_файла от git add .?

- git add имя_файла — добавляет в индекс только указанный файл.
- git add . — добавляет все изменения в текущей папке и подпапках.

Первый вариант удобен, когда нужно закоммитить только часть изменений. Второй — когда нужно добавить всё сразу.

## 5. Что показывает команда git status и как меняется её вывод?

Показывает состояние рабочей папки и индекса: какие файлы изменены, добавлены в индекс или не отслеживаются. Вывод меняется по этапам:
- после изменения файла — modified;
- после git add — Changes to be committed;
- после git commit — nothing to commit, working tree clean.

## 6. Для чего нужна команда git remote add origin URL и что означает слово "origin"?

Команда связывает локальный репозиторий с удалённым по указанному URL. Слово origin — это имя удалённого репозитория по умолчанию (псевдоним), 
чтобы не писать полный URL каждый раз.

## 7. Зачем нужен флаг -u в команде git push -u origin main?

Флаг -u (--set-upstream) связывает локальную ветку main с удалённой origin/main. После этого достаточно писать просто git push
 или git pull без указания ветки и remote.

## 8. Что такое ветка по умолчанию и какая у вас создалась?

Ветка по умолчанию — основная ветка репозитория, в которую вносятся изменения. Раньше Git создавал master, сейчас GitHub по умолчанию
 использует main. У меня изначально создалась master, затем я переименовала её в main командой git branch -M main. Это важно, потому что от имени ветки 
зависит, куда отправляются изменения и как настроены CI/CD и защита веток.

## 9. Как просмотреть историю коммитов и какую информацию видно?

Командой git log. Видно: хеш коммита, автора, дату и сообщение коммита. Краткий вид — git log --oneline.

## 10. Что произойдёт, если изменить файл, но не выполнить git add перед git commit?

Изменения не попадут в коммит. Git зафиксирует только то, что было в индексе. Файл останется изменённым в рабочей папке, а git status покажет его
 как modified, not staged.
