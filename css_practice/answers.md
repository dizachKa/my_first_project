# Ответы на вопросы (ПР3 — CSS)

## 1. Разница между селектором по классу и по ID

- **Класс (`.`)** — можно применять ко многим элементам на странице. Специфичность: 0,1,0.
- **ID (`#`)** — уникален, должен быть только один на странице. Специфичность: 1,0,0 (выше, чем у класса).

Для повторного использования лучше классы. ID — только когда элемент действительно один.

## 2. Как работает каскад в CSS

Каскад — это порядок применения стилей при конфликте. Браузер учитывает:
1. **Важность** — правила с `!important` идут первыми.
2. **Специфичность** — чем точнее селектор, тем выше приоритет.
3. **Порядок** — при равной специфичности побеждает то правило, что написано ниже в файле.

## 3. Специфичность селекторов

- `ul li.important` — **0,1,2** (1 класс + 2 тега)
- `#site-title` — **1,0,0** (1 ID)
- `.content > .featured-post` — **0,2,0** (2 класса)

## 4. Наследуемые и ненаследуемые свойства

**Наследуются:** `color`, `font-family`, `font-size`, `line-height`, `text-align`.
**Не наследуются:** `margin`, `padding`, `border`, `background`, `width`, `height`.

## 5. Разница между `>` и пробелом

- `.content > article` — **дочерний** селектор: выбирает только прямых детей.
- `.content article` — **потомок**: выбирает всех вложенных на любом уровне.

## 6. Псевдоклассы `:hover` и `:nth-child()`

- `:hover` — стиль при наведении мыши (кнопки, ссылки, карточки).
- `:nth-child()` — выбор элементов по порядку (чётные/нечётные строки таблицы, зебра).

## 7. Что делает `!important`

`!important` переопределяет все остальные правила, независимо от специфичности. Использовать осторожно — потому что он ломает естественный каскад и затрудняет поддержку.

## 8. Псевдоэлементы `::before` и `::after`

Они добавляют контент до или после элемента через свойство `content`. Могут содержать текст, символы, иконки. В моей работе: `→` перед карточкой и `★` после заголовка статьи.

## 9. Порядок применения при равной специфичности

Побеждает правило, которое **написано ниже** в CSS-файле. Если стили в разных файлах — важен порядок подключения `<link>`.

## 10. Как DevTools помогают отлаживать CSS

Инструменты разработчика (F12) позволяют:
- видеть, какие стили применились к элементу;
- видеть, какие правила перекрыты (зачёркнуты);
- анализировать специфичность;
- менять стили в реальном времени и сразу видеть результат;
- проверять наследование.
